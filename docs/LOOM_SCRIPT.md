# Loom demo script (target 4:30)

## Before you record (setup)
- **Two Android phones** with Google Play services (A = "walker", B = "observer"). One phone + an emulator image *with Google Play* can work as B, but the geofence exit must be on a **real phone** (A).
- Two accounts (use your own email addresses; e.g. `you+a@…`, `you+b@…`).
- Both phones: Orbit installed, notification permission granted, location "Allow all the time" (Settings → Orbit → Location), battery "Unrestricted". Stay on mobile data or Wi-Fi.
- Backend deployed (`firebase deploy …`), Maps key in `local.properties`.
- **Making a genuine exit on camera:** make the boundary ~150–300 m around where you stand and **walk out 300+ m**, or use a developer mock-location app on A (Developer options → "Select mock location app") to move out of the circle. Both are real device-level location changes — Orbit has no fake-event button. Allow up to 1–3 minutes for Android to deliver the transition: **record this part in a separate take** and cut/jump-cut the wait, saying so on camera.
- Have the Firebase console (Firestore) and the GitHub repo open in tabs.

## Script
| Time | Show | Say |
|---|---|---|
| 0:00 | Phone A: open Orbit, onboarding, sign in | "Orbit tells a group when someone leaves a place — and nothing else." |
| 0:25 | Create group "Trip", show invite code | "The code is generated by a Cloud Function and is guaranteed unique." |
| 0:45 | Phone B: sign in, **Join with code** | "B joins with the code; membership is validated server-side." |
| 1:10 | Phone A: **Set boundary** — use my location, 300 m, save | "Only owner/admins can do this — the function checks the role." |
| 1:35 | Both: Settings → permissions green; group shows **Monitoring active** | "Android needs 'Allow all the time' for background detection; Orbit tells you honestly when it's missing, unavailable or out of date." |
| 2:00 | Show Group Pulse "Waiting for first reports" → inside | "Pulse shows last-known status, never live location." |
| 2:15 | **Take 2:** A walks/mocks out; B's lock screen notification arrives | "Android's native geofencing detected the exit with Orbit closed. A got no alert; B did." |
| 3:00 | B: open group → Pulse "1 member is outside", timeline exit + time. A: confirm no notification | "Event written once, deduplicated server-side; the actor is excluded from recipients." |
| 3:20 | A returns → "came back" notification | "Same flow for re-entry." |
| 3:40 | Firestore console: `events` doc has name/type/time only | "No coordinates are stored." |
| 3:55 | Slides/README: architecture + sequence diagrams | "Compose + MVVM; geofencing → WorkManager → callable function; Firestore is read-only to clients; FCM via Admin SDK with retry and token pruning." |
| 4:20 | GitHub repo page, README, CI, test report | "Truthful test report included, including what still needs hardware." |

## If something can't be shown
- **No second phone:** show B via an emulator with Google Play; say so.
- **Transition doesn't fire in time:** keep the take; say Android delivery can lag minutes; show `adb shell dumpsys location | grep -i geofence` or retry with a larger radius (500 m+).
- **Notification missing:** check B's permission, battery setting, and Firebase console → Functions logs for `reportGeofenceEvent`. Don't fake it; record the real behaviour and fix first.
